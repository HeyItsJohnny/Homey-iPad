Homey-iPad password recovery UX refinement — November 4, 2026

SCOPE AND FLOW

Login now offers "Forgot My Password". The request screen uses "Forgot Your
Password?", the requested description, "Email Address", and "Reset Password".
Email trimming and validation happen before calling the existing isolated client.
A successful request changes recovery state to pendingVerification, which RootView
already presents automatically above normal authentication/household routing.

The pending reset screen shows "Reset Your Password", "Check your email to
continue.", the trimmed requested email, a same-iPad instruction, Resend Email,
and Back to Log In. The notice is account-neutral for every accepted request:
"If a Homey account exists for this email, we've sent a password reset link."
Password fields are hidden until successful PKCE exchange and server validation.
Resend uses the same email, existing 60-second cooldown and generic error handling.
Concurrent sends, resends and navigation during an in-flight resend are blocked.
The cooldown survives dismissal and reopening; it is not reset by navigation.

The existing strict callback handler now accepts callbacks from both idle and
pendingVerification. Verified callbacks reveal the password form immediately.
It uses the existing secure inputs, show/hide controls, inline errors, loading
state, duplicate protection and Supabase password policy. Empty confirmation
now has a specific required-field error. There was no account checkbox, checkbox
state or checkbox validation in this checkout, so none needed removal.

After server-confirmed update and recovery cleanup, the success screen shows
"Password Updated!", "Your Homey password has been successfully changed.",
"You can now log in using your new password.", a checkmark and Back to Log In.
The existing normal local sign-out path remains responsible for returning to login.

SECURITY PRESERVED

The separate Supabase client, isolated Keychain/PKCE namespace, SDK 2.53.0,
homeyipad://auth/reset-password redirect, strict URL validation, single-use code
exchange, identity and expiry checks before update, server-side password policy,
local recovery-session cleanup and transient password clearing remain intact.
The requested email is display/resend context only; it grants no update authority.
An existing household account never authorizes changes to the recovered account.
No account lookup, admin API, service-role credential, Resend API key, custom email
sender, extra confirmation step, iPhone callback or unrelated routing was added.

NATIVE PASSWORD CHANGED EMAIL — MANUAL DASHBOARD SETUP REQUIRED

The repository contains no supabase/config.toml, hosted Auth management setup,
or backend email templates. Hosted settings could not be read or changed from
this checkout. Current enablement, SMTP delivery and duplicate notifications
therefore remain unverified. No app-generated notification was added.

Supabase's native notification is triggered by the existing authenticated
update(user: UserAttributes(password:)) call when enabled for the project.
Configure it once for the shared backend; it also applies to other clients.

1. Open the Homey project in Supabase Dashboard.
2. Go to Authentication > Emails > Templates:
   https://supabase.com/dashboard/project/_/auth/templates
3. Under Security notifications, select Password changed and enable the
   notification. (The management field is
   mailer_notifications_password_changed_enabled = true.)
4. Set Subject to: Your Homey Password Was Changed
5. In the template source editor, paste Docs/password-changed-notification.html
   from this repository and save. The corresponding management fields are
   mailer_subjects_password_changed_notification and
   mailer_templates_password_changed_notification_content.
6. Verify the existing Resend SMTP configuration still uses
   noreply@homeyfamilyapp.com. Do not add a second notification through Resend,
   an Edge Function or an email hook. If a custom hook already delivers password
   change notifications, reconcile it before enabling this native path.
7. Keep Site URL https://homeyfamilyapp.com and both existing mobile redirects.
   Confirm homeyipad://auth/reset-password is allowlisted. Keep the recovery
   template's generated ConfirmationURL; do not replace it with a hard-coded
   device scheme. The password-changed notification template contains no links,
   passwords, tokens or session data.
8. Use a controlled test account for one real password change. Verify exactly
   one notification arrives with the exact subject and copy, from the configured
   sender. Failed/rejected password updates must not send a success notification.

Sources (official Supabase documentation, reviewed November 4, 2026):
https://supabase.com/docs/guides/auth/auth-email-templates
https://supabase.com/docs/guides/local-development/customizing-email-templates
